================================================================================
PIPER TTS SERVICE - GPU ACCELERATION GUIDE
================================================================================

This guide explains how to enable GPU acceleration for maximum performance.

================================================================================
IMPORTANT: SHOULD YOU USE GPU?
================================================================================

Piper TTS is already VERY fast on CPU. GPU acceleration provides:
  ✓ Slightly faster inference (~20-40% speedup)
  ✓ Better for high-concurrency scenarios
  ✓ Useful when GPU is already running other workloads

GPU may NOT be beneficial if:
  ✗ Single user / low concurrency
  ✗ CPU inference already < 0.1s per sentence
  ✗ GPU memory is limited
  ✗ Additional setup complexity

RECOMMENDATION:
  - For most use cases, CPU is sufficient and easier to setup
  - Use GPU for production deployments with high traffic
  - Test both and measure actual performance improvement

================================================================================
PREREQUISITES
================================================================================

1. NVIDIA GPU with CUDA support
   Check: nvidia-smi

2. CUDA Toolkit (11.x or 12.x)
   Download: https://developer.nvidia.com/cuda-downloads
   Verify: nvcc --version

3. cuDNN (matching CUDA version)
   Download: https://developer.nvidia.com/cudnn
   Install according to NVIDIA instructions

4. Check GPU is accessible:
   nvidia-smi

================================================================================
INSTALLATION - METHOD 1: FRESH INSTALL
================================================================================

If you haven't run setup.sh yet:

1. Edit config.py and enable GPU:
   
   # In config.py, change:
   use_gpu: bool = True  # Enable GPU acceleration
   gpu_device_id: int = 0  # GPU ID (0 for first GPU)

2. Run setup with GPU requirements:
   
   ./setup.sh
   source venv/bin/activate
   pip uninstall onnxruntime -y
   pip install -r requirements-gpu.txt

3. Start the service:
   
   ./start_service.sh

================================================================================
INSTALLATION - METHOD 2: UPGRADE EXISTING
================================================================================

If you already have the CPU version running:

1. Stop the service:
   
   ./stop_service.sh

2. Activate environment and upgrade:
   
   source venv/bin/activate
   pip uninstall onnxruntime -y
   pip install -r requirements-gpu.txt

3. Edit config.py to enable GPU:
   
   # In config.py, around line 20:
   use_gpu: bool = True
   gpu_device_id: int = 0

4. Start the service:
   
   ./start_service.sh

5. Check logs for GPU detection:
   
   tail -f tts_service.log
   
   You should see:
   "✓ GPU support available (CUDA)"
   "GPU Info: [your GPU details]"

================================================================================
VERIFY GPU IS BEING USED
================================================================================

1. Start the service with GPU enabled

2. In another terminal, monitor GPU usage:
   
   watch -n 1 nvidia-smi

3. Run test client:
   
   python test_client.py

4. You should see GPU utilization increase during synthesis

5. Check service logs:
   
   grep "GPU" tts_service.log

================================================================================
CONFIGURATION
================================================================================

GPU settings in config.py:

class ServiceConfig(BaseModel):
    # GPU Configuration
    use_gpu: bool = True           # Enable/disable GPU
    gpu_device_id: int = 0         # GPU ID (for multi-GPU systems)

For multiple GPUs:
  - Set gpu_device_id to select GPU (0, 1, 2, etc.)
  - Or set CUDA_VISIBLE_DEVICES environment variable

================================================================================
PERFORMANCE COMPARISON
================================================================================

Typical performance (English synthesis, ~50 words):

CPU (Intel i7):
  - Processing time: ~0.3-0.5 seconds
  - RTF (Real-Time Factor): ~0.15-0.25x
  - Suitable for: Most applications

GPU (NVIDIA RTX 3090):
  - Processing time: ~0.2-0.3 seconds
  - RTF: ~0.10-0.15x
  - Suitable for: High-traffic production

The improvement is modest because:
  1. Piper models are small and optimized
  2. ONNX Runtime is already very efficient
  3. Overhead of GPU data transfer

================================================================================
TROUBLESHOOTING
================================================================================

Issue: "GPU requested but CUDA not available"
Solution:
  - Check CUDA installation: nvcc --version
  - Check GPU visibility: nvidia-smi
  - Reinstall CUDA toolkit
  - Verify cuDNN is installed

Issue: "onnxruntime-gpu not found"
Solution:
  pip uninstall onnxruntime onnxruntime-gpu -y
  pip install onnxruntime-gpu==1.16.3

Issue: "CUDA version mismatch"
Solution:
  - Check CUDA version: nvcc --version
  - Check onnxruntime-gpu requirements
  - Install matching version:
    CUDA 11.x: pip install onnxruntime-gpu==1.16.3
    CUDA 12.x: pip install onnxruntime-gpu==1.17.0

Issue: GPU not being utilized
Solution:
  - Check use_gpu=True in config.py
  - Verify CUDAExecutionProvider in logs
  - Check CUDA_VISIBLE_DEVICES is not set to empty
  - Ensure piper binary supports GPU (may need custom build)

Issue: Out of memory errors
Solution:
  - Reduce concurrent requests
  - Use smaller batch sizes
  - Monitor GPU memory: nvidia-smi
  - Set gpu_device_id to use different GPU

================================================================================
MULTI-GPU SETUP
================================================================================

To use specific GPU:

1. Option A - Config file:
   gpu_device_id: int = 1  # Use second GPU

2. Option B - Environment variable:
   export CUDA_VISIBLE_DEVICES=1
   ./start_service.sh

3. Option C - Run multiple instances:
   # Instance 1 on GPU 0
   CUDA_VISIBLE_DEVICES=0 python tts_server.py --port 8003
   
   # Instance 2 on GPU 1
   CUDA_VISIBLE_DEVICES=1 python tts_server.py --port 8004

================================================================================
MONITORING GPU USAGE
================================================================================

Real-time monitoring:
  watch -n 1 nvidia-smi

Detailed metrics:
  nvidia-smi dmon -s pucvmet

GPU process info:
  nvidia-smi pmon

Log GPU stats to file:
  nvidia-smi --query-gpu=timestamp,name,utilization.gpu,memory.used \
    --format=csv -l 1 > gpu_stats.log

================================================================================
BENCHMARK TOOL
================================================================================

Create benchmark.py to test CPU vs GPU:

```python
import time
import requests

def benchmark(num_requests=100):
    text = "This is a benchmark test for TTS performance."
    times = []
    
    for i in range(num_requests):
        start = time.time()
        response = requests.post(
            "http://localhost:8003/synthesize",
            json={"text": text}
        )
        elapsed = time.time() - start
        times.append(elapsed)
        
        if (i + 1) % 10 == 0:
            print(f"Completed {i + 1}/{num_requests}")
    
    avg_time = sum(times) / len(times)
    print(f"\nAverage time: {avg_time:.3f}s")
    print(f"Throughput: {1/avg_time:.1f} req/s")

if __name__ == "__main__":
    benchmark()
```

Run with CPU, then GPU, and compare results.

================================================================================
COST-BENEFIT ANALYSIS
================================================================================

GPU Setup Time:
  - CUDA installation: 30-60 minutes
  - Driver updates: 10-20 minutes
  - Configuration: 5-10 minutes
  Total: ~1-2 hours

CPU Setup Time:
  - Standard install: 5 minutes
  Total: 5 minutes

Performance Gain:
  - Latency improvement: 20-40%
  - Throughput improvement: 30-50% (high concurrency)

When GPU is Worth It:
  ✓ Production environment with >10 requests/second
  ✓ GPU already available for other workloads
  ✓ Need lowest possible latency
  ✓ Running multiple TTS models simultaneously

When CPU is Better:
  ✓ Development/testing
  ✓ Low traffic (<5 requests/second)
  ✓ Simpler deployment
  ✓ Cost-sensitive deployment

================================================================================
FALLBACK BEHAVIOR
================================================================================

The service automatically falls back to CPU if:
  - GPU not available
  - CUDA not installed
  - onnxruntime-gpu not installed
  - GPU out of memory

No manual intervention needed - service continues running on CPU.

Check logs for fallback messages:
  "⚠ GPU requested but CUDA not available"
  "Falling back to CPU"

================================================================================
DOCKER DEPLOYMENT WITH GPU
================================================================================

For containerized deployment with GPU:

1. Use NVIDIA Container Toolkit:
   distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
   curl -s -L https://nvidia.github.io/nvidia-docker/gpgkey | sudo apt-key add -
   curl -s -L https://nvidia.github.io/nvidia-docker/$distribution/nvidia-docker.list | \
     sudo tee /etc/apt/sources.list.d/nvidia-docker.list
   sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit

2. Create Dockerfile with GPU support:
   FROM nvidia/cuda:11.8.0-cudnn8-runtime-ubuntu22.04
   # ... rest of setup

3. Run with GPU:
   docker run --gpus all -p 8003:8003 piper-tts-service
